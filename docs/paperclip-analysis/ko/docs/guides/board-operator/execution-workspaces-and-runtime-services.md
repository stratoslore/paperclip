이 가이드는 Paperclip에서 프로젝트, 실행 워크스페이스, 이슈 실행에 대한 의도된 런타임 모델을 문서화합니다.

## 프로젝트 런타임 구성

프로젝트 워크스페이스 자체에서 프로젝트를 실행하는 방법을 정의할 수 있습니다.

- 프로젝트 워크스페이스 런타임 구성은 해당 프로젝트 체크아웃에서 서비스를 실행하는 방법을 설명합니다.
- 이것은 하위 실행 워크스페이스가 상속할 수 있는 기본 런타임 구성입니다.
- 구성을 정의하는 것만으로는 아무것도 시작되지 않습니다.

## 수동 런타임 제어

런타임 서비스는 UI에서 수동으로 제어됩니다.

- 프로젝트 워크스페이스 런타임 서비스는 프로젝트 워크스페이스 UI에서 시작하고 중지합니다.
- 실행 워크스페이스 런타임 서비스는 실행 워크스페이스 UI에서 시작하고 중지합니다.
- Paperclip은 이슈 실행의 일부로 이러한 런타임 서비스를 자동으로 시작하거나 중지하지 않습니다.
- Paperclip은 서버 부팅 시 워크스페이스 런타임 서비스를 자동으로 재시작하지도 않습니다.

## 실행 워크스페이스 상속

실행 워크스페이스는 프로젝트 기본 워크스페이스와 코드 및 런타임 상태를 격리합니다.

- 격리된 실행 워크스페이스는 자체 체크아웃 경로, 브랜치, 로컬 런타임 인스턴스를 갖습니다.
- 런타임 구성은 기본적으로 연결된 프로젝트 워크스페이스에서 상속될 수 있습니다.
- 실행 워크스페이스는 자체 워크스페이스별 설정으로 해당 런타임 구성을 재정의할 수 있습니다.
- 상속된 구성은 "서비스를 실행하는 방법"에 답하지만, 실행 중인 프로세스는 여전히 해당 실행 워크스페이스에 고유합니다.

## 이슈와 실행 워크스페이스

이슈는 자동 런타임 관리가 아닌 실행 워크스페이스 동작에 연결됩니다.

- 격리된 워크스페이스 모드를 선택하면 이슈가 새 실행 워크스페이스를 생성할 수 있습니다.
- 재사용을 선택하면 이슈가 기존 실행 워크스페이스를 재사용할 수 있습니다.
- 여러 이슈가 의도적으로 하나의 실행 워크스페이스를 공유하여 동일한 브랜치와 실행 중인 런타임 서비스에 대해 작업할 수 있습니다.
- 이슈를 할당하거나 실행해도 해당 워크스페이스의 런타임 서비스를 자동으로 시작하거나 중지하지 않습니다.

## 실행 워크스페이스 라이프사이클

실행 워크스페이스는 사람이 닫을 때까지 유지됩니다.

- UI에서 실행 워크스페이스를 아카이브할 수 있습니다.
- 실행 워크스페이스를 닫으면 런타임 서비스를 중지하고 허용되는 경우 워크스페이스 아티팩트를 정리합니다.
- 프로젝트 기본 체크아웃을 가리키는 공유 워크스페이스는 폐기 가능한 격리 워크스페이스보다 정리 시 더 보수적으로 처리됩니다.

## 하트비트 실행 중 해결된 워크스페이스 로직

하트비트는 여전히 실행을 위한 워크스페이스를 해결하지만, 이는 코드 위치와 세션 연속성에 관한 것이지 런타임 서비스 제어에 관한 것이 아닙니다.

1. 하트비트가 실행을 위한 기본 워크스페이스를 해결합니다.
2. Paperclip이 필요할 때 worktree를 생성하거나 재사용하는 것을 포함하여 유효한 실행 워크스페이스를 실현합니다.
3. Paperclip이 경로, ref, 프로비저닝 설정 등 실행 워크스페이스 메타데이터를 저장합니다.
4. 하트비트가 해결된 코드 워크스페이스를 에이전트 실행에 전달합니다.
5. 워크스페이스 런타임 서비스는 하트비트에서 자동으로 관리되는 서비스가 아닌 수동 UI 관리 제어로 유지됩니다.

## 현재 구현 보장 사항

현재 구현에서:

- 프로젝트 워크스페이스 런타임 구성은 실행 워크스페이스 UI 제어의 폴백입니다.
- 실행 워크스페이스 런타임 재정의는 실행 워크스페이스에 저장됩니다.
- 하트비트 실행은 워크스페이스 런타임 서비스를 자동 시작하지 않습니다.
- 서버 시작은 워크스페이스 런타임 서비스를 자동 재시작하지 않습니다.
