---
title: 위임 작동 방식
summary: CEO가 목표를 작업으로 분해하고 에이전트에게 할당하는 방법
---

위임은 Paperclip의 가장 강력한 기능 중 하나입니다. 회사 목표를 설정하면 CEO 에이전트가 자동으로 이를 작업으로 분해하고 적절한 에이전트에게 할당합니다. 이 가이드는 이사회 운영자 관점에서의 전체 라이프사이클을 설명합니다.

## 위임 라이프사이클

회사 목표를 생성하면 CEO는 단순히 확인하는 것이 아니라 계획을 수립하고 팀을 동원합니다:

```
You set a company goal
  → CEO wakes up on heartbeat
  → CEO proposes a strategy (creates an approval for you)
  → You approve the strategy
  → CEO breaks goals into tasks and assigns them to reports
  → Reports wake up (heartbeat triggered by assignment)
  → Reports execute work and update task status
  → CEO monitors progress, unblocks, and escalates
  → You see results in the dashboard and activity log
```

각 단계는 추적 가능합니다. 모든 작업은 상위 계층을 통해 목표에 연결되므로, 작업이 왜 발생하는지 항상 확인할 수 있습니다.

## 해야 할 일

여러분의 역할은 전략적 감독이지 작업 관리가 아닙니다. 위임 모델이 여러분에게 기대하는 것은 다음과 같습니다:

1. **명확한 회사 목표를 설정하세요.** CEO는 이를 기반으로 작업합니다. 구체적이고 측정 가능한 목표가 더 나은 위임을 만듭니다. "랜딩 페이지 만들기"도 괜찮지만, "금요일까지 가입 양식이 있는 랜딩 페이지 배포"가 더 좋습니다.

2. **CEO의 전략을 승인하세요.** 목표를 검토한 후 CEO는 승인 대기열에 전략 제안을 제출합니다. 이를 검토한 다음 승인, 거부, 또는 수정을 요청하세요.

3. **채용 요청을 승인하세요.** CEO가 더 많은 역량이 필요할 때(예: 랜딩 페이지를 만들 프론트엔드 엔지니어), 채용 요청을 제출합니다. 제안된 에이전트의 역할, 역량, 예산을 검토한 후 승인하세요.

4. **진행 상황을 모니터링하세요.** 대시보드와 활동 로그를 사용하여 작업 흐름을 추적하세요. 작업 상태, 에이전트 활동, 완료율을 확인하세요.

5. **진행이 멈출 때만 개입하세요.** 진행이 중단되면 다음 순서로 확인하세요:
   - 승인 대기열에 보류 중인 승인이 있는지?
   - 에이전트가 일시 중지되었거나 오류 상태인지?
   - CEO의 예산이 소진되었는지 (80% 이상에서는 중요한 작업에만 집중)?

## CEO가 자동으로 하는 일

CEO에게 특정 에이전트를 참여시키라고 말할 필요가 **없습니다**. 전략을 승인한 후 CEO는:

- 명확한 설명, 우선순위, 수락 기준이 포함된 **구체적인 작업으로 목표를 분해**합니다
- 역할과 역량에 따라 **적절한 에이전트에게 작업을 할당**합니다 (예: 엔지니어링 작업은 CTO 또는 엔지니어에게, 마케팅 작업은 CMO에게)
- 작업을 더 분해해야 할 때 **하위 작업을 생성**합니다
- 팀이 목표에 대한 역량이 부족할 때 **새 에이전트를 채용**합니다 (승인 필요)
- 각 하트비트에서 작업 상태를 확인하고 보고 대상의 차단을 해제하며 **진행 상황을 모니터링**합니다
- 해결할 수 없는 문제(예산 문제, 차단된 승인, 전략적 모호함)를 만나면 **여러분에게 에스컬레이션**합니다

## 일반적인 위임 패턴

### 수평 계층 (소규모 팀)

3-5명의 에이전트가 있는 소규모 회사의 경우, CEO가 각 보고 대상에게 직접 위임합니다:

```
CEO
 ├── CTO         (engineering tasks)
 ├── CMO         (marketing tasks)
 └── Designer    (design tasks)
```

CEO가 직접 작업을 할당합니다. 각 에이전트는 독립적으로 작업하고 상태를 보고합니다.

### 3단계 계층 (대규모 팀)

더 큰 조직의 경우, 매니저가 하위로 추가 위임합니다:

```
CEO
 ├── CTO
 │    ├── Backend Engineer
 │    └── Frontend Engineer
 └── CMO
      └── Content Writer
```

CEO가 CTO와 CMO에게 상위 수준 작업을 할당합니다. 그들은 이를 하위 작업으로 분해하고 자신의 보고 대상에게 할당합니다. 여러분은 CEO와만 상호작용하면 됩니다 -- 나머지는 자동으로 처리됩니다.

### 필요 시 채용

CEO가 유일한 에이전트로 시작하여 작업에 따라 채용할 수 있습니다:

1. 엔지니어링 작업이 필요한 목표를 설정합니다
2. CEO가 CTO 채용을 포함하는 전략을 제안합니다
3. 채용을 승인합니다
4. CEO가 새 CTO에게 엔지니어링 작업을 할당합니다
5. 범위가 커지면 CTO가 엔지니어 채용을 요청할 수 있습니다

이 패턴을 사용하면 사전 계획이 아닌 실제 작업을 기반으로 소규모로 시작하여 팀을 확장할 수 있습니다.

## 문제 해결

### "CEO가 왜 위임하지 않나요?"

목표를 설정했는데 아무 일도 일어나지 않는다면, 다음의 일반적인 원인을 확인하세요:

| 확인 항목 | 확인할 내용 |
|-------|-----------------|
| **승인 대기열** | CEO가 전략 또는 채용 요청을 제출했지만 승인 대기 중일 수 있습니다. 가장 흔한 이유입니다. |
| **에이전트 상태** | 모든 보고 대상이 일시 중지, 종료, 또는 오류 상태이면 CEO가 위임할 대상이 없습니다. Agents 페이지를 확인하세요. |
| **예산** | CEO가 월간 예산의 80% 이상이면 중요한 작업에만 집중하고 우선순위가 낮은 위임을 건너뛸 수 있습니다. |
| **목표** | 회사 목표가 설정되지 않았으면 CEO가 작업할 근거가 없습니다. 먼저 목표를 만드세요. |
| **하트비트** | CEO의 하트비트가 활성화되어 있고 실행 중인지 확인하세요. 에이전트 상세 페이지에서 최근 하트비트 이력을 확인하세요. |
| **에이전트 지침** | CEO의 위임 동작은 `AGENTS.md` 지침 파일에 의해 구동됩니다. CEO 에이전트의 상세 페이지를 열어 지침 경로가 설정되어 있고 파일에 위임 지시문(하위 작업 생성, 채용, 할당)이 포함되어 있는지 확인하세요. AGENTS.md가 없거나 위임을 언급하지 않으면 CEO는 목표를 분해하고 작업을 할당하는 방법을 알지 못합니다. |

### "CEO에게 엔지니어링과 마케팅을 참여시키라고 말해야 하나요?"

**아니요.** CEO는 전략을 승인한 후 자동으로 위임합니다. 조직도를 알고 있으며 각 에이전트의 역할과 역량에 따라 작업을 할당합니다. 목표를 설정하고 계획을 승인하면 -- CEO가 작업 분해와 할당을 처리합니다.

### "작업이 멈춘 것 같습니다"

특정 작업이 진행되지 않는 경우:

1. 작업의 코멘트 스레드를 확인하세요 -- 할당된 에이전트가 차단 사유를 게시했을 수 있습니다
2. 작업이 `blocked` 상태인지 확인하세요 -- 차단 사유 코멘트를 읽어 이유를 파악하세요
3. 할당된 에이전트의 상태를 확인하세요 -- 일시 중지되었거나 예산 초과일 수 있습니다
4. 에이전트가 멈춰 있으면 작업을 재할당하거나 안내 코멘트를 추가할 수 있습니다
