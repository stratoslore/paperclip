# 에이전트 런타임 가이드

상태: 사용자 대상 가이드
최종 업데이트: 2026-02-17
대상: Paperclip에서 에이전트를 설정하고 실행하는 운영자

## 1. 이 시스템이 하는 일

Paperclip의 에이전트는 연속적으로 실행되지 않습니다.
**하트비트**로 실행됩니다: 웨이크업에 의해 트리거되는 짧은 실행 시간대입니다.

각 하트비트는:

1. 구성된 에이전트 어댑터를 시작합니다 (예: Claude CLI 또는 Codex CLI)
2. 현재 프롬프트/컨텍스트를 전달합니다
3. 종료, 타임아웃 또는 취소될 때까지 작업하게 합니다
4. 결과를 저장합니다 (상태, 토큰 사용량, 오류, 로그)
5. UI를 실시간으로 업데이트합니다

## 2. 에이전트가 깨어날 때

에이전트는 네 가지 방법으로 깨어날 수 있습니다:

- `timer`: 예약된 간격 (예: 5분마다)
- `assignment`: 해당 에이전트에게 작업이 할당/체크아웃될 때
- `on_demand`: 수동 웨이크업 (버튼/API)
- `automation`: 향후 자동화를 위한 시스템 트리거 웨이크업

에이전트가 이미 실행 중인 경우, 새 웨이크업은 중복 실행을 시작하는 대신 병합(통합)됩니다.

## 3. 에이전트별 구성 항목

## 3.1 어댑터 선택

일반적인 선택:

- `claude_local`: 로컬 `claude` CLI를 실행
- `codex_local`: 로컬 `codex` CLI를 실행
- `process`: 범용 쉘 명령 어댑터
- `http`: 외부 HTTP 엔드포인트를 호출

`claude_local`과 `codex_local`의 경우, Paperclip은 CLI가 이미 호스트 머신에 설치되고 인증되어 있다고 가정합니다.

## 3.2 런타임 동작

에이전트 런타임 설정에서 하트비트 정책을 구성합니다:

- `enabled`: 예약된 하트비트 허용
- `intervalSec`: 타이머 간격 (0 = 비활성화)
- `wakeOnAssignment`: 작업 할당 시 깨우기
- `wakeOnOnDemand`: 핑 방식의 온디맨드 웨이크업 허용
- `wakeOnAutomation`: 시스템 자동화 웨이크업 허용

## 3.3 작업 디렉토리 및 실행 제한

로컬 어댑터의 경우 설정:

- `cwd` (작업 디렉토리)
- `timeoutSec` (하트비트당 최대 실행 시간)
- `graceSec` (타임아웃/취소 후 강제 종료 전 대기 시간)
- 선택적 환경 변수 및 추가 CLI 인수

## 3.4 프롬프트 템플릿

설정 가능:

- `promptTemplate`: 모든 실행에 사용 (첫 실행 및 재개된 세션)

템플릿은 `{{agent.id}}`, `{{agent.name}}` 및 실행 컨텍스트 값과 같은 변수를 지원합니다.

## 4. 세션 재개 동작

Paperclip은 `(agent, taskKey, adapterType)`별로 재개 가능한 세션 상태를 저장합니다.
`taskKey`는 웨이크업 컨텍스트(`taskKey`, `taskId`, 또는 `issueId`)에서 파생됩니다.

- 동일한 task key에 대한 하트비트는 해당 작업의 이전 세션을 재사용합니다.
- 같은 에이전트의 다른 task key는 별도의 세션 상태를 유지합니다.
- 복원에 실패하면, 어댑터는 새 세션으로 한 번 재시도하고 계속해야 합니다.
- 에이전트의 모든 세션을 초기화하거나 task key로 하나의 작업 세션을 초기화할 수 있습니다.

세션 초기화를 사용할 때:

- 프롬프트 전략을 크게 변경한 경우
- 에이전트가 나쁜 루프에 빠진 경우
- 깨끗한 재시작을 원하는 경우

## 5. 로그, 상태 및 실행 이력

각 하트비트 실행에 대해 다음을 얻습니다:

- 실행 상태 (`queued`, `running`, `succeeded`, `failed`, `timed_out`, `cancelled`)
- 오류 텍스트 및 stderr/stdout 발췌
- 어댑터에서 제공하는 경우 토큰 사용량/비용
- 전체 로그 (대용량 출력에 최적화되어 코어 실행 행 외부에 저장)

로컬/개발 설정에서는 구성된 실행 로그 경로 아래 디스크에 전체 로그가 저장됩니다.

## 6. UI의 실시간 업데이트

Paperclip은 런타임/활동 업데이트를 실시간으로 브라우저에 푸시합니다.

다음의 실시간 변경을 확인할 수 있습니다:

- 에이전트 상태
- 하트비트 실행 상태
- 에이전트 작업으로 인한 작업/활동 업데이트
- 관련 대시보드/비용/활동 패널

연결이 끊어지면 UI가 자동으로 재연결합니다.

## 7. 일반적인 운영 패턴

## 7.1 단순 자율 루프

1. 타이머 웨이크업 활성화 (예: 300초마다)
2. 할당 웨이크업 유지
3. 집중된 프롬프트 템플릿 사용
4. 실행 로그를 관찰하고 시간이 지남에 따라 프롬프트/구성 조정

## 7.2 이벤트 기반 루프 (일정한 폴링 감소)

1. 타이머 비활성화 또는 긴 간격 설정
2. 할당 시 깨우기 활성화 유지
3. 수동 촉구를 위해 온디맨드 웨이크업 사용

## 7.3 안전 우선 루프

1. 짧은 타임아웃
2. 보수적인 프롬프트
3. 오류 모니터링 + 필요 시 빠른 취소
4. 드리프트가 나타나면 세션 초기화

## 8. 문제 해결

실행이 반복적으로 실패하는 경우:

1. 어댑터 명령 가용성 확인 (`claude`/`codex` 설치 및 로그인 확인).
2. `cwd`가 존재하고 접근 가능한지 확인.
3. 실행 오류 + stderr 발췌를 검사한 후 전체 로그 확인.
4. 타임아웃이 너무 낮지 않은지 확인.
5. 세션 초기화 후 재시도.
6. 반복적으로 잘못된 업데이트를 유발하는 경우 에이전트 일시 중지.

일반적인 실패 원인:

- CLI가 설치되지 않거나/인증되지 않음
- 잘못된 작업 디렉토리
- 잘못된 어댑터 인수/환경 변수
- 프롬프트가 너무 넓거나 제약이 없음
- 프로세스 타임아웃

## 9. 보안 및 위험 참고

로컬 CLI 어댑터는 호스트 머신에서 샌드박싱 없이 실행됩니다.

이는 다음을 의미합니다:

- 프롬프트 지시사항이 중요합니다
- 구성된 자격 증명/환경 변수는 민감합니다
- 작업 디렉토리 권한이 중요합니다

가능한 한 최소 권한으로 시작하고, 의도적으로 필요한 경우가 아니면 넓은 재사용 가능 프롬프트에서 비밀을 노출하지 마세요.

## 10. 최소 설정 체크리스트

1. 어댑터 선택 (`claude_local` 또는 `codex_local`).
2. `cwd`를 대상 워크스페이스로 설정.
3. 부트스트랩 + 일반 프롬프트 템플릿 추가.
4. 하트비트 정책 구성 (타이머 및/또는 할당 웨이크업).
5. 수동 웨이크업 트리거.
6. 실행 성공 및 세션/토큰 사용량 기록 확인.
7. 실시간 업데이트를 관찰하고 프롬프트/구성 반복.
