# Paperclip 사양

Paperclip 컨트롤 플레인의 목표 사양입니다. 사양 인터뷰 중 점진적으로 업데이트되는 살아있는 문서입니다.

---

## 1. 회사 모델 [초안]

회사(Company)는 일급 객체입니다. 하나의 Paperclip 인스턴스가 여러 회사를 운영합니다. 회사는 독립적인 "목표" 필드가 없습니다 — 방향은 이니셔티브 집합으로 정의됩니다 (작업 계층 매핑 참조).

### 필드 (초안)

| 필드       | 유형          | 참고                             |
| ----------- | ------------- | --------------------------------- |
| `id`        | uuid          | 기본 키                       |
| `name`      | string        | 회사 이름                      |
| `createdAt` | timestamp     |                                   |
| `updatedAt` | timestamp     |                                   |

### 보드 거버넌스 [초안]

모든 회사에는 고영향 의사결정을 관리하는 **보드**가 있습니다. 보드는 인간 감독 레이어입니다.

**V1: 단일 인간 보드.** 한 명의 인간 운영자.

#### 보드 승인 게이트 (V1)

- 새 에이전트 고용 (새 에이전트 생성)
- CEO의 초기 전략적 분석 (CEO가 제안, 보드가 실행 시작 전에 승인)
- [미정: 기타 거버넌스 게이트 동작 — 목표 변경, 에이전트 해고?]

#### 보드 권한 (항상 사용 가능)

보드는 전체 시스템에 대해 항상 **무제한 접근**이 가능합니다:

- **회사 예산 설정 및 수정** — 보드가 최상위 토큰/LLM 비용 예산을 설정
- **모든 에이전트 일시정지/재개** — 에이전트의 하트비트를 즉시 중지
- **모든 작업 항목 일시정지/재개** — 작업, 프로젝트, 하위작업 트리, 마일스톤을 일시정지. 일시정지된 항목은 에이전트에 의해 픽업되지 않음.
- **전체 프로젝트 관리 접근** — UI를 통해 모든 작업/프로젝트/마일스톤을 생성, 편집, 댓글, 수정, 삭제, 재할당
- **모든 에이전트 결정 오버라이드** — 작업 재할당, 우선순위 변경, 설명 수정
- **모든 수준에서 예산을 수동 변경**

보드는 단순한 승인 게이트가 아닙니다 — 실시간 제어 화면입니다. 인간은 어떤 수준에서든 언제든 개입할 수 있습니다.

#### 예산 위임

보드가 회사 수준 예산을 설정합니다. CEO는 하위 에이전트의 예산을 설정할 수 있고, 모든 관리자 에이전트도 보고자에 대해 동일하게 할 수 있습니다. 이 계단식 예산 위임이 실제로 어떻게 작동하는지는 미정이지만, 권한 구조는 이를 지원합니다. 보드는 어떤 수준에서든 수동으로 예산을 오버라이드할 수 있습니다.

**향후 거버넌스 모델** (V1 아님):

- 고용 예산 (월 $X 이내 자동 승인)
- 다중 구성원 보드
- 위임된 권한 (CEO가 제한 내에서 고용 가능)

### 미해결 질문

- 외부 수입/지출 추적 — 향후 플러그인. 토큰/LLM 비용 예산은 코어.
- 회사 수준 설정과 구성?
- 회사 수명주기 (일시정지, 보관, 삭제)?
- 고용과 CEO 전략 승인 외에 어떤 거버넌스 게이트 동작이 있는가?

## 2. 에이전트 모델 [초안]

모든 직원은 에이전트입니다. 에이전트는 인력입니다.

### 에이전트 아이덴티티 (어댑터 수준)

SOUL.md(아이덴티티/미션)나 HEARTBEAT.md(루프 정의)와 같은 개념은 **Paperclip 프로토콜의 일부가 아닙니다**. 어댑터별 구성입니다. 예를 들어, OpenClaw 어댑터는 SOUL.md와 HEARTBEAT.md 파일을 사용할 수 있고, Claude Code 어댑터는 CLAUDE.md를 사용할 수 있고, 베어 Python 스크립트는 명령줄 인수를 사용할 수 있습니다.

Paperclip은 에이전트가 아이덴티티나 동작을 정의하는 방법을 규정하지 않습니다. 컨트롤 플레인을 제공하고, 어댑터가 에이전트의 내부 작동을 정의합니다.

### 에이전트 구성 [초안]

각 에이전트는 **어댑터 유형**과 **어댑터별 구성 blob**을 가집니다. 어댑터가 어떤 설정 필드가 존재하는지 정의합니다.

#### Paperclip 프로토콜 (Paperclip이 아는 것)

프로토콜 수준에서 Paperclip은 다음을 추적합니다:

- 에이전트 아이덴티티 (id, name, role, title)
- 조직 위치 (보고 대상, 보고자)
- 어댑터 유형 + 어댑터 설정
- 상태 (active, paused, terminated)
- 비용 추적 데이터 (에이전트가 보고하는 경우)

#### 어댑터 구성 (에이전트별)

각 어댑터 유형은 자체 설정 스키마를 정의합니다. 예시:

- **OpenClaw 어댑터**: SOUL.md 내용, HEARTBEAT.md 내용, OpenClaw 관련 설정
- **Process 어댑터**: 실행할 명령, 환경 변수, 작업 디렉토리
- **HTTP 어댑터**: 엔드포인트 URL, 인증 헤더, 페이로드 템플릿

#### 내보내기 가능한 조직 설정

핵심 목표: **전체 조직의 에이전트 설정을 내보낼 수 있습니다.** 회사의 전체 에이전트 설정 — 모든 에이전트, 어댑터 설정, 조직 구조 — 을 이식 가능한 아티팩트로 내보낼 수 있습니다. 이를 통해:

- 회사 템플릿 공유 ("미리 구축된 마케팅 에이전시 조직")
- 회사 설정의 버전 관리
- 회사 복제/포크

#### 컨텍스트 전달

에이전트별로 구성 가능. 스펙트럼의 두 끝:

- **팻 페이로드** — Paperclip이 관련 컨텍스트(현재 작업, 메시지, 회사 상태, 메트릭)를 하트비트 호출에 번들링. Paperclip에 콜백할 수 없는 단순/무상태 에이전트에 적합.
- **씬 핑** — 하트비트는 단순한 깨우기 신호. 에이전트가 Paperclip API를 호출하여 필요한 컨텍스트를 가져옴. 자체 상태를 관리하는 정교한 에이전트에 적합.

#### 최소 계약

Paperclip 에이전트가 되기 위한 최소 요구사항: **호출 가능.** 그것이 전부. Paperclip이 명령이나 웹훅을 통해 호출할 수 있습니다. 보고할 필요 없음 — Paperclip은 가능한 경우 프로세스 활성도에서 기본 상태를 추론합니다.

#### 통합 수준

최소 요구 이상으로 Paperclip은 점진적으로 풍부한 통합을 제공합니다:

1. **호출 가능** (최소) — Paperclip이 시작할 수 있음. 유일한 계약.
2. **상태 보고** — 에이전트가 실행 후 성공/실패/진행 중을 보고.
3. **완전 계측** — 에이전트가 상태, 비용/토큰 사용량, 작업 업데이트, 로그를 보고. 컨트롤 플레인과의 양방향 통합.

Paperclip은 전체 통합을 보여주는 **기본 에이전트**를 제공합니다: 진행 추적, 비용 계측, 작업 관리를 위한 **Paperclip 스킬** (Paperclip API와 상호작용하기 위한 Claude Code 스킬). 유용한 기본값과 어댑터 작성자를 위한 참조 구현 역할을 합니다.

#### 내보내기 형식

두 가지 내보내기 모드:

1. **템플릿 내보내기** (기본) — 구조만: 에이전트 정의, 조직도, 어댑터 설정, 역할 설명. 선택적으로 시작을 돕기 위한 몇 가지 시드 작업 포함. 새 회사를 시작하기 위한 청사진.
2. **스냅샷 내보내기** — 전체 상태: 구조 + 현재 작업, 진행, 에이전트 상태. 복원하거나 포크할 수 있는 완전한 그림.

일반적인 워크플로우: 템플릿을 내보내고, 그것에서 새 회사를 생성하고, 초기 작업 몇 개를 추가하고, 시작.

## 3. 조직 구조 [초안]

계층적 보고 구조. CEO가 최상위, 보고가 아래로 계단식.

### 에이전트 가시성

**조직 전체 완전한 가시성.** 모든 에이전트가 전체 조직도, 모든 작업, 모든 에이전트를 볼 수 있습니다. 조직 구조는 **보고 및 위임 라인**을 정의하지, 접근 제어가 아닙니다.

각 에이전트는 자신의 책임과 능력에 대한 짧은 설명을 게시합니다 — 거의 스킬처럼 ("내가 관련될 때"). 이를 통해 다른 에이전트가 무엇을 도울 수 있는지 발견할 수 있습니다.

### 교차 팀 작업

에이전트는 보고 라인 외부의 에이전트에게 작업을 생성하고 할당할 수 있습니다. 이것이 교차 팀 협업 메커니즘입니다.

#### 청구 코드

작업은 **청구 코드**를 가지므로 실행 중 토큰 지출을 요청 작업/에이전트에 상류로 귀속시킬 수 있습니다.

### 미해결 질문

- 엄격한 트리인가 아니면 에이전트가 여러 관리자에게 보고할 수 있는가?
- 조직 구조가 런타임에 변경될 수 있는가? (에이전트 재배치, 팀 재구성)
- 에이전트가 관리자로부터 구성을 상속하는가?
- 청구 코드 형식 — 단순 문자열? 계층적?

## 4. 하트비트 시스템 [초안]

하트비트는 프로토콜이지 런타임이 아닙니다. Paperclip은 에이전트의 사이클을 시작하는 방법을 정의합니다. 에이전트가 그 사이클로 무엇을 하는지 — 얼마나 오래 실행하는지, 작업 범위인지 연속적인지 — 는 전적으로 에이전트에게 달려 있습니다.

### 실행 어댑터

에이전트 구성에는 Paperclip이 에이전트를 호출하는 방법을 정의하는 **어댑터**가 포함됩니다. 내장 어댑터:

| 어댑터 | 메커니즘 | 예시 |
| ---------------- | -------------------------- | -------------------------------------------------- |
| `process` | 자식 프로세스 실행 | `python run_agent.py --agent-id {id}` |
| `http` | HTTP 요청 전송 | `POST https://openclaw.example.com/hook/{id}` |
| `claude_local` | 로컬 Claude Code 프로세스 | Claude Code 하트비트 워커 |
| `codex_local` | 로컬 Codex 프로세스 | Codex CLI 하트비트 워커 |
| `opencode_local` | 로컬 OpenCode 프로세스 | OpenCode 하트비트 워커 |
| `pi_local` | 로컬 Pi 프로세스 | Pi CLI 하트비트 워커 |
| `cursor` | Cursor API/CLI 브리지 | Cursor 통합 하트비트 워커 |
| `openclaw_gateway` | OpenClaw 게이트웨이 API | 관리형 OpenClaw 에이전트 (게이트웨이 경유) |
| `hermes_local` | 로컬 Hermes 프로세스 | Hermes 에이전트 하트비트 워커 |

`process`와 `http` 어댑터는 범용 기본값으로 제공됩니다. 추가 내장 어댑터는 일반적인 로컬 코딩 런타임을 다루며(위 목록 참조), 새 어댑터 유형은 플러그인 시스템을 통해 등록할 수 있습니다(플러그인/확장 아키텍처 참조).

### 어댑터 인터페이스

모든 어댑터는 세 가지 메서드를 구현합니다:

```
invoke(agentConfig, context?) → void     // 에이전트의 사이클 시작
status(agentConfig) → AgentStatus        // 실행 중? 완료? 오류?
cancel(agentConfig) → void               // 우아한 중지 신호 (일시정지/재개용)
```

이것이 전체 어댑터 계약입니다. `invoke`는 에이전트를 시작하고, `status`는 Paperclip이 확인할 수 있게 하고, `cancel`은 보드의 일시정지 기능을 활성화합니다. 그 외 모든 것(비용 보고, 작업 업데이트)은 선택사항이며 Paperclip REST API를 통해 흐릅니다.

### Paperclip이 제어하는 것

- 하트비트를 **언제** 발사할지 (스케줄/빈도, 에이전트별)
- **어떻게** 발사할지 (어댑터 선택 + 설정)
- **어떤 컨텍스트**를 포함할지 (씬 핑 vs 팻 페이로드, 에이전트별)

### Paperclip이 제어하지 않는 것

- 에이전트가 얼마나 오래 실행하는지
- 에이전트가 사이클 동안 무엇을 하는지
- 에이전트가 작업 범위인지, 시간 윈도우인지, 연속적인지

### 일시정지 동작

보드(또는 시스템)가 에이전트를 일시정지할 때:

1. **현재 실행에 신호** — 실행 중인 프로세스/세션에 우아한 종료 신호 전송
2. **유예 기간** — 에이전트가 마무리하고, 상태를 저장하고, 최종 상태를 보고할 시간 부여
3. **타임아웃 후 강제 종료** — 유예 기간 내에 에이전트가 중지하지 않으면 종료
4. **향후 하트비트 중지** — 에이전트가 재개될 때까지 새 하트비트 사이클이 발사되지 않음

이것은 "우아한 신호 + 향후 하트비트 중지"입니다. 현재 실행이 깨끗하게 랜딩할 기회를 얻습니다.

## 5. 에이전트 간 통신 [초안]

모든 에이전트 통신은 **작업 시스템**을 통해 흐릅니다.

### 모델: 작업 + 댓글

- **위임** = 작업을 생성하고 다른 에이전트에게 할당
- **조정** = 작업에 댓글
- **상태 업데이트** = 작업 상태 및 필드 업데이트

별도의 메시징이나 채팅 시스템은 없습니다. 작업이 통신 채널입니다. 이를 통해 모든 컨텍스트가 관련 작업에 첨부되고 자연스러운 감사 추적이 생성됩니다.

## 6. 비용 추적 [초안]

토큰/LLM 비용 예산은 Paperclip의 핵심입니다. 외부 수입 및 지출 추적은 향후 플러그인입니다.

### 예산 제어

세 단계:

1. **가시성** — 모든 수준(에이전트, 작업, 프로젝트, 회사)에서 지출을 보여주는 대시보드
2. **소프트 알림** — 구성 가능한 임계값 (예: 예산의 80%에서 경고)
3. **하드 상한** — 예산에 도달하면 에이전트 자동 일시정지. 보드에 알림. 보드가 제한을 오버라이드/상향 가능.

## 8. 아키텍처 및 배포 [초안]

### 배포 모델

**단일 테넌트, 자체 호스팅.** SaaS가 아님. 하나의 인스턴스 = 한 운영자의 회사들.

### 기술 스택

| 레이어    | 기술                                                   |
| -------- | ------------------------------------------------------------ |
| 프론트엔드 | React + Vite                                                 |
| 백엔드  | TypeScript + Express (REST API, tRPC 아님 — 비TS 클라이언트 필요) |
| 데이터베이스 | PostgreSQL ([doc/DATABASE.md](./doc/DATABASE.md) 참조 — 개발용 PGlite 내장, Docker 또는 호스팅 Supabase) |
| 인증     | [Better Auth](https://www.better-auth.com/)                  |

### 플러그인/확장 아키텍처

핵심 Paperclip 시스템은 확장 가능해야 합니다. 지식 베이스, 외부 수입 추적, 새 에이전트 어댑터와 같은 기능은 코어를 수정하지 않고 **플러그인**으로 추가할 수 있어야 합니다.

플러그인 프레임워크가 출시되었습니다. 플러그인은 새 어댑터 유형을 등록하고, 수명주기 이벤트에 연결하고, UI 컴포넌트(예: 글로벌 도구 모음 버튼)를 기여할 수 있습니다. 플러그인 SDK와 CLI 명령(`paperclipai plugin`)이 플러그인 작성 및 설치에 사용 가능합니다.

## 12. 반요구사항

Paperclip이 명시적으로 **하지 않는** 것:

- **에이전트 런타임이 아님** — Paperclip이 오케스트레이션, 에이전트는 다른 곳에서 실행
- **지식 베이스가 아님** — 코어에 위키/문서/벡터DB 없음 (플러그인 영역)
- **SaaS가 아님** — 단일 테넌트, 자체 호스팅
- **에이전트 구현에 대한 의견 없음** — 모든 언어, 프레임워크, 런타임
- **자동 자가 치유 아님** — 문제를 표면화, 자동으로 수정하지 않음
- **배포 인프라 관리 안 함** — 저장소 관리, 배포, 파일 시스템 없음 (단, 작업 연결 문서와 첨부 파일은 관리)
- **작업 자동 재할당 안 함** — 오래된 작업은 표면화, 자동으로 재분배되지 않음
- **외부 수입/지출 추적 안 함** — 향후 플러그인. 토큰/LLM 비용 예산은 코어.

## 13. 원칙 (통합)

1. **에이전트 실행 방법에 대한 의견 없음.** 모든 언어, 프레임워크, 런타임. Paperclip은 컨트롤 플레인이지 실행 플레인이 아닙니다.
2. **회사가 조직 단위.** 모든 것이 회사 아래에 존재합니다.
3. **작업이 통신 채널.** 모든 에이전트 통신은 작업 + 댓글을 통해 흐릅니다. 사이드 채널 없음.
4. **모든 작업은 목표로 추적.** 계층적 작업 관리 — 고립되어 존재하는 것 없음.
5. **보드가 관리.** 인간이 보드를 통해 제어 유지. 보수적인 기본값 (인간 승인 필요).
6. **문제를 표면화, 숨기지 않음.** 좋은 감사와 가시성. 자동 복구 없음.
7. **원자적 소유권.** 작업당 단일 담당자. 원자적 체크아웃으로 충돌 방지.
8. **점진적 배포.** 로컬 시작이 간단하고, 호스팅으로 확장이 쉬움.
9. **확장 가능한 코어.** 플러그인이 코어 수정 없이 기능(어댑터, 지식 베이스, 수입 추적)을 추가할 수 있는 깨끗한 경계.
